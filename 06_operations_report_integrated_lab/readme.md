# 6단계 · 운영 리포트 작성 및 통합 실습

## 이론적 배경

가드레일은 한 번 구현하고 끝나는 기능이 아니라 새로운 공격 패턴, 정책 변경, 오탐·미탐 결과에 따라 계속 조정해야 하는 운영 체계다. 따라서 탐지와 차단의 결과를 기간별로 정리하고, 다음 개선 작업으로 연결하는 피드백 루프가 필요하다.

6단계에서는 앞선 결과를 하나의 실행 흐름과 운영 리포트로 통합한다. 특히 더미 응답과 실제 로컬 LLM 응답이 동일한 방어 계층을 통과하는지 확인해 설계와 운영 결과 사이의 차이를 줄인다.

## 학습 목표

가드레일과 관제 결과를 주간·월간 운영 리포트로 정리하고 전체 흐름을 통합한다.

## 핵심 내용

- 탐지 건수·차단 건수·검토 건수
- 차단율과 위험 등급 분포
- 미대응 이슈와 다음 주 개선 과제
- 정책 변경 전후 비교와 운영 의사결정

## 이론 보강

운영 리포트는 탐지 결과를 나열하는 문서가 아니라 다음 운영 결정을 돕는 문서다. 기간, 기준선, 변화량, 원인, 대응 상태, 다음 개선 과제를 같은 문맥에 배치해야 한다.

주간 리포트는 최근 사건과 즉시 조치를 중심으로 작성하고, 월간 리포트는 추세·정책 변경 효과·반복 오탐·미대응 누적을 분석한다. 동일한 지표 정의를 유지해야 기간 간 비교가 가능하다.

통합 실습에서는 입력 판정, 출력 검열, 위험 등급, 이벤트 집계, Critical 알림이 서로 다른 결과를 내지 않는지 확인한다. 각 단계의 이벤트 ID를 연결하면 한 요청의 전체 처리 경로를 추적할 수 있다.

## 실습

```bash
python3 -m unittest discover -s tests -v
python3 06_operations_report_integrated_lab/src/app.py
```

선택적으로 `USE_LLM=1`을 지정하면 `src/llm.py`가 로컬 Ollama의 `/api/chat`을 호출한다. 모델 응답은 더미 응답과 동일하게 입력 검사와 출력 검열을 거친다.

실행 결과에서 입력 판정, 출력 검열, 이벤트 생성, Critical 알림, 리포트 지표를 차례로 확인한다.

실행이 끝나면 최종 JSON은 `results/step06-report.json`에 저장된다.

```bash
python3 -m json.tool results/step06-report.json
```
