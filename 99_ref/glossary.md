# 용어 정리 — 전체 단계 통합 용어집

1~6단계 학습 자료에서 사용하는 핵심 용어를 단계별로 모았다. 각 용어는 해당 단계 readme의 개요 탭 용어집과 동일한 내용이다.

## 단계별 용어

### 1단계 · Guardrail 개념과 아키텍처

| 용어 | 설명 |
| --- | --- |
| Guardrail | 모델 호출 전후에 정책을 집행하는 통제 계층 — 모델 자체가 아닌 운영 계층 |
| PII | 개인식별정보 — 이름·연락처·주민번호 등 개인을 식별할 수 있는 정보 |
| PipelineStage | 파이프라인 각 단계를 추상화한 실행 단위 (architecture.py) |
| 관제 | 이벤트 기록·대응 연결 — 파이프라인의 항상 실행되는 마지막 단계 |
| 규칙 ID | 발동된 정책 규칙을 추적하기 위한 식별자 |
| 더미 모델 | 실제 LLM 없이 결정적 응답을 반환하는 연습용 모델 |
| 민감정보 | 외부 노출 시 피해가 되는 정보 — PII·비밀키·내부 데이터 등 |
| 보안 이벤트 | 차단·검토·허용 판정의 기록 단위 — 운영의 기본 데이터 |
| 보존기간 | 로그·원문 데이터를 보관하는 기간 정책 |
| 안전한 기본값 | 통제 계층이 실패해도 안전하게 동작하도록 하는 기본 반환값 |
| 운영 로그 | 판정 결과·규칙 ID·위험 등급·이벤트 ID를 우선 기록하는 로그 |
| 위험 등급 | 이벤트의 심각도를 Low~Critical으로 분류한 라벨 |
| 유해 요청 | 폭력·불법·유해 콘텐츠 생성이나 조장을 요구하는 입력 |
| 이벤트 ID | 보안 이벤트를 고유하게 식별하는 ID |
| 입력 가드레일 | 모델 호출 전 요청의 목적·권한·위험 신호를 검사 |
| 접근권한 | 원문 로그 열람을 제한하는 권한 설정 |
| 정책 집행 지점 | 규칙을 실제로 적용하는 코드 위치 — 입력·출력 각각에 존재 |
| 출력 가드레일 | 모델 응답이 공개되어도 되는지 호출 후 다시 검사 |
| 출력 검열 | 모델 생성 결과에서 민감정보·유해성을 걸러내는 출력 단계 검사 |
| 통제 계층 | 모델 앞뒤에 정책 집행 지점을 두는 운영 구조 |
| 프롬프트 인젝션 | 지시문을 조작해 모델의 원래 목적을 우회하는 공격 |
| 허용·차단·검토 | 판정 결과 3단계 — 통과·거부·사람 확인 필요 |

### 2단계 · Llama Guard·NeMo Guardrails

| 용어 | 설명 |
| --- | --- |
| GPU 메모리 | Transformers 경로에서 모델 로드에 필요한 자원 |
| Llama Guard | 요청·응답의 안전성 범주를 분류하는 안전성 판정 모델 |
| NeMo Guardrails | 대화 주제·절차·응답 경로를 정책으로 제어하는 대화 흐름 프레임워크 |
| Ollama | 로컬 LLM 실행 백엔드 — 학습용 기본 경로 |
| PyTorch | Transformers 경로의 딥러닝 런타임 |
| Transformers | HuggingFace 모델 직접 로드 경로 — 심화 옵션 |
| custom adapter | NeMo에서 전용 분류 모델을 연결하는 어댑터 |
| llama_guard.py | Llama Guard 실제 호출 모듈 (classifier/) |
| nemo_guardrails_client.py | NeMo Guardrails 호출 모듈 (dialogue/) |
| not_responsible_for | 각 기술이 대신하지 않는 책임을 명시하는 필드 |
| real_integration.py | 실제 모델 호출 파이프라인 (pipeline/) |
| receives→produces→handoff_to | 어댑터 계약 3요소 — 입력·출력·다음 단계 |
| 대화 정책 | 허용된 주제와 응답 경로를 정의하는 규칙 집합 |
| 대화 흐름 제어 | 대화가 특정 주제·절차를 벗어나지 않도록 하는 제어 |
| 모델 가중치 | 학습된 파라미터 — Llama Guard 직접 실행 시 추가 관리 대상 |
| 분류기(classifier) | 위험성을 범주로 판정하는 역할 — 최종 결정은 내리지 않음 |
| 사람 검토 | 자동 판정이 어려운 사건을 담당자가 확인하는 경로 |
| 안전성 분류 | 입력/출력이 허용 범주인지 판정하는 분류 작업 |
| 어댑터 | 외부 기술을 내부 계약으로 연결하는 계층 — src/contracts/adapters.py |
| 오탐 | 정상 입력을 위험으로 잘못 판정하는 오류 |
| 위험 카테고리 | 폭력·혐오·개인정보 등 Llama Guard의 분류 범주 |
| 응답 경로 | 모델이 답변을 생성하는 경로 — 정책이 허용 범위를 결정 |
| 정책 우선순위 | 중복 차단 방지를 위한 적용 순서 규칙 |
| 주제 이탈 | 허용된 주제를 벗어난 발화 — NeMo가 복귀·검토로 전환 |
| 최종 결정 | 차단·검토·허용의 실제 판정 — 애플리케이션 정책 계층의 역할 |
| 탐지 결과 | 분류기가 산출하는 위험 판정값 — 정책 엔진의 입력값 |

### 4단계 · 위험 등급 체계

| 용어 | 설명 |
| --- | --- |
| Critical | 즉시 알림·에스컬레이션이 필요한 최고 위험 등급 |
| High | 담당자 검토·차단을 요구하는 높은 위험 등급 |
| Low | 추세 관찰 수준의 최저 위험 등급 |
| Medium | 일상 모니터링 대상의 중간 위험 등급 |
| SecurityEvent | 위험 판정을 운영 이벤트로 변환한 기록 구조 |
| classify_risk | 영향·악용·노출 점수를 Low~Critical으로 변환 |
| event_from_guardrail_file | 3단계 결과 JSON을 SecurityEvent로 변환 |
| risk.py | 3축 점수→등급 분류·이벤트 변환 모듈 |
| step04-security-event.json | 4단계 결과 — 5단계 API 전달 파일 |
| write_event_result | 이벤트를 step04-security-event.json으로 저장 |
| 긴급도 | 대응이 필요한 시간적 급박함 |
| 대응 계약 | 등급이 올라갈수록 강한 조치를 연결하는 규칙 |
| 등급 변경 기록 | 변경자·시각·사유를 별도 기록 — 원본 덮어쓰기 금지 |
| 민감도 | 노출된 데이터·시스템의 민감 정도 |
| 사후 분석 | 사건 종료 후 원인·대응을 분석하는 절후 활동 |
| 악용 가능성 | 공격자가 실제로 악용할 수 있는 정도 |
| 에스컬레이션 | 상위 담당자·팀으로 사건을 escalation하는 절차 |
| 영향 범위 | 사고 발생 시 피해가 미치는 범위 |
| 위험 등급 | 영향·악용 가능성·노출 범위로 정한 대응 강도 단계 |
| 이벤트 ID·시각·카테고리·판정·상세 | 이벤트에 남겨야 할 필수 필드 |
| 즉시 알림 | Critical 등급에 발송되는 긴급 통지 |
| 행동 기준 | 등급을 숫자가 아닌 구체적 조치로 정의한 기준 |

### 5단계 · 보안 대시보드와 알림
