단계 간 실습 결과 전달

각 단계의 소스코드는 독립·중복 유지한다. 단계 간 연결은 공통 Python import가 아니라 JSON 결과 파일 또는 5단계 HTTP API로 전달한다.

03단계 결과 → step03-guardrail-result.json
04단계 이벤트 → step04-security-event.json
05단계 지표 → step05-metrics.json
06단계 통합 리포트 → step06-report.json
파일생성 단계다음 사용 단계
step03-guardrail-result.json정책 차단·출력 검열4단계 위험 등급
step04-security-event.json위험 등급·이벤트 생성5단계 API·대시보드
step05-metrics.jsonAPI 지표 집계6단계 운영 리포트
step06-report.json통합 실행최종 제출·개선안

결과 확인 명령

python3 -m json.tool results/step03-guardrail-result.json
python3 -m json.tool results/step04-security-event.json
python3 -m json.tool results/step05-metrics.json
python3 -m json.tool results/step06-report.json

5단계 결과는 API 서버에서 GET /metrics로 조회하며, 응답을 step05-metrics.json으로 저장하면 6단계가 자동으로 읽는다. 각 JSON의 schema_version, event_id, trace_id, decision, risk, category, metrics, upstream_metrics 필드를 중심으로 단계별 결과를 확인한다.

점층 통합 실습

01~06 폴더는 독립 학습용으로 유지한다. 이 디렉터리는 단계별 코드를 수정하거나 공통 import로 묶지 않고, 실제 서비스가 단계적으로 확장되는 모습을 별도 실행 트랙으로 제공한다.

01 architecture
  → 02 model policy
  → 03 guardrail
  → 04 risk
  → 05 monitoring
  → 06 reporting

각 단계는 이전 단계의 결과 규약을 읽지만, 다음 규칙을 따른다.

  • 단계 폴더의 소스코드는 직접 수정하지 않는다.
  • 단계 폴더끼리 공통 Python import를 만들지 않는다.
  • 결과 파일은 integration/results/에 별도로 저장한다.
  • 규약 변경은 contracts/의 버전을 올린다.
  • 독립 단계 실습은 이전 단계 결과 없이도 실행 가능하게 유지한다.

실행

python3 integration/run.py --stage 01
python3 integration/run.py --stage 02
python3 integration/run.py --stage 03
python3 integration/run.py --stage 04
python3 integration/run.py --stage 05
python3 integration/run.py --stage 06

전체 점층 흐름은 다음처럼 실행한다.

python3 integration/run.py --all

실제 2단계 Guardrail 호출은 5단계 API를 통해 수행한다. 서버를 실행한 뒤 다음 요청을 보내면 NeMo Guardrails와 Llama Guard의 결과가 SQLite 이벤트로 저장된다.

uvicorn api:app --app-dir 05_security_dashboard_alerts/src --port 8000
curl -X POST http://127.0.0.1:8000/guardrail/chat \
  -H 'Content-Type: application/json' \
  -H 'X-API-Key: dev-only-key' \
  -d '{"message":"안전한 업무 요청입니다"}'

이 경로는 integration/guardrail_service.py에서 03_policy_blocking_output_filtering의 입력·출력 정책과 2단계 실제 provider를 연결한다. provider 초기화 또는 호출이 실패하면 API는 503을 반환한다.

통합 결과는 integration/results/에 기록되며, 기존 results/의 독립 실습 결과와 분리된다.
